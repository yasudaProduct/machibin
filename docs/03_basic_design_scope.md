## 1. 目的

本書は、要件定義書（01）で定義した機能・非機能要件、およびアーキテクチャ設計書（02）で選定した技術方式をもとに、**基本設計工程で作成すべきドキュメントを洗い出す**ことを目的とする。各ドキュメントの記載内容・主な参照元・優先度を明確化し、以降の基本設計作業の計画・スコープ合意に用いる。

## 2. 基本設計工程の位置づけ

| 工程 | 既存文書 | 内容 |
| --- | --- | --- |
| 要件定義 | `01_requirements.md` | 提供価値・機能要件（FR-01〜14）・非機能要件・データ要件・外部IF要件を定義（WHAT/WHY） |
| アーキテクチャ設計（方式設計） | `02_architecture.md` | 技術スタック・システム構成・主要データフロー・コスト試算を決定（技術方式のHOW） |
| **基本設計（本書が対象）** | 本書以降で作成 | 上記を踏まえ、**機能・画面・データ・インターフェースの外部仕様**を、詳細設計・実装に着手できる粒度まで具体化する |
| 詳細設計・実装 | — | 基本設計を受けてコード・クラス・モジュール単位に落とし込む |

> 02_architecture.md は技術選定と全体構成（方式設計）を既に担っているため、本書で洗い出す基本設計ドキュメントは、それを前提とした**機能仕様・画面仕様・データ仕様・IF仕様・運用仕様**の具体化に主眼を置く。

## 4. 優先度と進め方（個人開発〜小規模チーム向け）

要件定義書・アーキテクチャ設計書ともに「個人開発〜小規模チーム」を前提としているため、企業システム開発の標準的な基本設計成果物をすべて独立文書として作成するのではなく、以下のように**統合・簡略化**することを推奨する。

| グループ | 対応ドキュメント | 方針 |
| --- | --- | --- |
| コア（必ず個別文書化） | D-01 機能設計書、D-02 画面設計書、D-03 データベース設計書（+D-04コード設計を包含）、D-05 API設計書、D-07 バッチ設計書 | Phase 1（MVP）実装前に必須。UC-01（投函→交換→配達→受信）を一気通貫で仕様化できる粒度で作成する |
| 重点統合 | D-06 外部IF設計書、D-08 通知設計書、D-09 認証・認可設計書 | 「連携先設計書」として1文書に統合可能（Clerk／Resend／Expo Push／地図タイルをまとめて記載） |
| プライバシー・運用 | D-10 運営管理機能設計書、D-11 プライバシー・データ保護設計書、D-12 セキュリティ設計書、D-13 非機能要件詳細設計書 | D-11は要件定義§5.4が「重点項目」とする通り独立文書を推奨。D-10・D-12・D-13は「運用・非機能補足書」として1文書に統合可能 |
| 省略可 | D-14 環境・CI/CD設計書、D-15 テスト方針書、D-16 用語集拡張版 | 02_architecture.md §9の記載で当面代替可。必要になった時点で追補する |
